# Memory & Context Persistence Skill (메모리 유지 스킬)

## 개요
Claude가 대화창을 닫거나 컨텍스트가 초기화되어도, 이전 작업의 맥락을 이어갈 수 있도록 하는 **기억력 유지 시스템**.

> **핵심 원칙**: 모든 작업은 "메모 읽기 → 작업 → 메모 쓰기"로 감싼다.

---

## 1. 컨텍스트 유지 필수 워크플로우

### 작업 시작 시 (필수)
```
[세션 시작] → PROGRESS.md 읽기 → 이전 맥락 파악 → 작업 시작
```

**Claude는 코딩을 시작하기 전에 반드시 아래 파일들을 순서대로 읽어야 한다:**

1. **`PROGRESS.md`** (프로젝트 루트) — 마지막 작업 상태, 미해결 에러, 다음 계획
2. **`MEMORY.md`** (auto-memory) — 프로젝트 구조, 패턴, 중요 결정사항
3. **관련 skill 문서** — 해당 작업과 관련된 스킬 문서 (예: `webtoonskill.md`)

**읽은 후 반드시 확인할 것:**
- 마지막으로 어떤 작업을 했는지
- 미해결된 에러나 TODO가 있는지
- 다음 단계로 계획된 작업이 무엇인지

### 작업 종료/중단 시 (필수)
```
[작업 완료/중단] → PROGRESS.md 업데이트 → 사용자에게 보고
```

**아래 상황을 감지하면 즉시 PROGRESS.md를 업데이트한다:**
- 사용자가 "여기까지", "오늘은 이만", "다음에", "저장해줘" 등 종료 뉘앙스 발언
- 사용자가 `/clear` 또는 대화 초기화 요청
- 큰 작업 단위가 완료되었을 때 (커밋 후 등)
- 에러가 발생하여 작업이 막혔을 때

**PROGRESS.md에 기록할 내용:**
```markdown
## 마지막 작업 (날짜)
- 무엇을 했는지 (핵심 변경사항 3줄 이내)
- 수정한 파일 목록

## 미해결 이슈
- 남아있는 에러나 TODO

## 다음 단계
- 이어서 할 작업 계획

## 최근 변경 로직 (핵심만)
- 왜 그렇게 했는지 간단한 이유
```

## 2. 상황별 행동 규칙 (조건 → 행동)

### 코드 품질 규칙
| 상황 | 행동 |
|---|---|
| 에러가 날 수 있는 외부 API 호출 | 반드시 try-catch로 감싸고, 사용자 친화적 에러 메시지 반환 |
| 새 파일을 생성할 때 | 파일 최상단에 1줄짜리 주석으로 이 파일의 역할 설명 |
| 함수가 30줄을 넘어갈 때 | 논리 단위로 분리하여 별도 함수로 추출 |
| 같은 코드가 3번 이상 반복될 때 | 공통 유틸 함수로 추출 |
| DB 쿼리를 작성할 때 | 에러 핸들링 + 결과 null 체크 필수 |

### AI/Gemini 관련 규칙
| 상황 | 행동 |
|---|---|
| Gemini API 호출 시 | 반드시 재시도 로직 포함 (최소 2회, temperature 낮춰서) |
| JSON 파싱이 필요한 Gemini 응답 | robustJSONParse 사용, 마크다운 코드블록 제거 포함 |
| 이미지 생성 실패 시 | 텍스트 데이터는 먼저 저장, 이미지는 나중에 재생성 가능하도록 |
| Supabase Storage 업로드 시 | 기존 파일 절대 삭제 금지, 새 파일명(timestamp)으로 생성 |

### Git 관련 규칙
| 상황 | 행동 |
|---|---|
| 커밋 전 | PROGRESS.md가 업데이트되었는지 확인 |
| 큰 기능 완료 후 | 사용자에게 커밋 여부를 묻기 (자동 커밋 금지) |
| .env 파일 변경 감지 | 절대 커밋하지 않고 경고 |

### 에러 대응 규칙
| 상황 | 행동 |
|---|---|
| 같은 에러가 2번 연속 발생 | 접근 방식을 바꿔서 시도 (무한 재시도 금지) |
| 500 에러 (외부 API) | 10초 대기 후 1회 재시도, 실패 시 사용자에게 보고 |
| 타입 에러 (TypeScript) | 기존 프로젝트의 타입 패턴을 먼저 확인 후 수정 |
| 빌드 에러 | 에러 메시지 전문을 읽고, 관련 파일을 확인한 후 수정 |

## 3. PROGRESS.md 파일 규칙

### 파일 위치
- `D:\claude\onsia-Job\onsia-job\PROGRESS.md` (프로젝트 루트)

### 업데이트 빈도
- **필수**: 세션 시작 시 읽기, 세션 종료 시 쓰기
- **권장**: 큰 작업 단위 완료마다 중간 업데이트
- **긴급**: 에러로 작업이 막혔을 때 즉시 기록

### 크기 제한
- 최대 100줄 이내 유지 (오래된 내용은 MEMORY.md로 이관)
- 최근 3개 세션 분량만 유지, 이전 내용은 아카이브

### MEMORY.md와의 역할 분담
| 파일 | 역할 | 내용 |
|---|---|---|
| `PROGRESS.md` | 단기 기억 | 현재 진행 상황, 미해결 이슈, 다음 계획 |
| `MEMORY.md` | 장기 기억 | 프로젝트 구조, 패턴, 주요 결정, 해결된 이슈 |

### 이관 규칙
- 해결 완료된 이슈 → MEMORY.md의 해당 섹션으로 이동
- 3회 이상 반복 참조되는 패턴 → MEMORY.md에 패턴으로 등록
- 오래된(2주+) PROGRESS.md 항목 → 삭제 또는 MEMORY.md로 아카이브

## 4. Hooks 연동 가이드 (자동 강제 시스템)

> Hooks = "스킬(매뉴얼)대로 안 하면 작업을 막아버리는 안전장치"

### 개념
스킬이 "이렇게 해라"라는 **가이드**라면, Hooks는 "안 하면 차단"하는 **강제 장치**.

### 적용 가능한 Hook 시나리오

**Pre-Commit Hook (커밋 전 체크)**:
- PROGRESS.md가 최근 1시간 내 업데이트되지 않았으면 → 커밋 차단 + "메모장부터 먼저 적으세요" 경고
- `.env` 파일이 staged에 포함되면 → 커밋 차단 + "환경변수 파일은 커밋할 수 없습니다" 경고

**Pre-Push Hook (푸시 전 체크)**:
- TypeScript 빌드 에러가 있으면 → 푸시 차단

**Session Start Hook (세션 시작 시)**:
- PROGRESS.md 자동 읽기 트리거
- 마지막 업데이트가 24시간 이상 전이면 → "PROGRESS.md가 오래되었습니다" 알림

### Claude Code settings.json Hook 설정 예시
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "if [[ \"$TOOL_INPUT\" == *\"git commit\"* ]]; then if ! git diff --name-only HEAD 2>/dev/null | grep -q 'PROGRESS.md'; then echo 'WARN: PROGRESS.md가 업데이트되지 않았습니다. 먼저 진행상황을 기록하세요.'; fi; fi"
          }
        ]
      }
    ]
  }
}
```

## 5. 스킬 간 연동

### webtoonskill.md 연동
뉴스툰 생성 작업 시:
1. 시작 전: PROGRESS.md에서 마지막 에피소드 번호, 미해결 이슈 확인
2. 완료 후: PROGRESS.md에 생성된 에피소드 정보 기록

### 다른 스킬 추가 시
모든 새 스킬 문서에 아래 섹션을 반드시 포함:
```markdown
## 컨텍스트 연동
- 시작 전 확인: [PROGRESS.md에서 확인할 항목]
- 완료 후 기록: [PROGRESS.md에 기록할 항목]
```
