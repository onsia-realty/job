## 1. 이 문서의 목적과 사용법

Claude Code 또는 Codex CLI에서 프로젝트의 부족한 부분을 순서대로 보완하기 위한 실행 가능한 체크리스트다. 체크박스는 실제 검증 결과가 있을 때만 완료로 변경한다. 진행 중 발견한 문제·결정·범위 변경은 아래 작업 기록에 추가한다.

이 문서는 실행 권한을 부여하는 명령서가 아니다. 문서를 읽거나 평가하는 요청만으로 운영 DB 변경, 결제, 배포, 커밋을 실행하지 않는다. 사용자가 구현을 요청한 범위 안에서 진행한다.

시작 시 읽을 자료:

1. 저장소에 적용되는 지침 파일과 `CLAUDE.md`
2. `docs/HANDOFF_CODEX.md`
3. `PROGRESS.md`, `docs/stay-progress.md`
4. 이 문서와 현재 `git status`, 작업 대상의 실제 코드

문서와 코드가 다르면 현재 코드와 재검증 결과를 우선한다. 과거 기록의 DB 적용·배포 성공은 현재 환경에서 재확인하기 전까지 확정 사실로 취급하지 않는다.

## 4. 작업 보존 및 검증 규칙

- 시작할 때 `git status --short --branch`와 대상 diff를 읽는다.
- 기존 Claude 작업은 사용자 소유다. 삭제·되돌리기·일괄 덮어쓰기를 하지 않는다.
- 중첩된 기존 작업을 수정해야 하면 diff를 이해하고 현재 동작을 보존하면서 필요한 부분만 수정한다.
- 분석·로컬 구현·운영 변경을 구분한다. 운영 SQL, 실결제, 발행, 배포, push는 명시된 요청 범위를 확인한다.
- `.env` 값과 토큰을 로그·문서·커밋에 기록하지 않는다. 환경변수는 필요한 키의 존재만 확인한다.
- 기존 dev 서버를 확인하고 중복 실행이나 무단 종료를 피한다. 동시 build가 dev 출력에 영향을 줄 가능성도 확인한다.
- 지도 변경은 브라우저 스크린샷과 상호작용으로 검증한다.
- HTTP 점검은 User-Agent를 지정하고 상태 코드와 기대 응답을 함께 확인한다.
- 단기임대 금액은 원 단위 `_won`, 시세 금액은 만원 단위다.
- 단기임대 서버 통제 필드를 Zod 화이트리스트에 추가하거나 `.passthrough()`로 풀지 않는다.

- SQL 실행은 대상 Supabase 프로젝트와 적용 상태부터 확인한다. 앱과 별개 CRM 프로젝트를 혼동하지 않는다.
