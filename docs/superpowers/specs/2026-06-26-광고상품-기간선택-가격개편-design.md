# 광고상품 기간선택 가격 개편 — 설계 스펙

- **작성일**: 2026-06-26
- **브랜치**: `feature/ad-pricing-duration-2026-06-26`
- **벤치마크**: 분양의신(bunshin.kr) `/jobs/register` 유료 노출 등급 구조

---

## 1. 목표

공인중개사·분양상담사 광고 상품을 **4등급 × 기간선택(10/20/30일)** 구조로 개편한다.
분양의신처럼 한 등급 안에서 기간을 고르면 가격이 비례해 바뀌고, "20일 구매 시 +10일 무료"
보너스로 체감 가치를 높인다. 현재의 "특별가(10배 할인)"는 걷어내고 정가를 실가격으로 승격한다.

핵심 메시지: **"분양의신 광고비의 약 1/5 가격"** — 압도적 저가를 전면에 깔되, 등급 구조는
프리미엄하게 보이게 한다.

## 2. 현재 상태와 문제

- **가격 출처가 2곳으로 분리** → 어긋나면 결제 버그 직결
  - `src/app/premium/page.tsx`의 `PRICING_DATA` (화면 표시: 정가 49k/99k/249k 취소선 + 특별가 4.9k/9.9k/24.9k)
  - `src/lib/toss.ts`의 `PAYMENT_PRODUCTS` (실제 결제: 4.9k/9.9k/24.9k)
- **3등급 고정 기간** — 한 등급 안에서 기간을 고를 수 없음
- 현재 4,900~24,900원대는 **테스트용 미끼 가격** (실 결제 고객 없음 → 인상 리스크 없음)
- 너무 저렴해 B2B(분양대행사·중개사무소)에 "정식 서비스"로 인식되지 않음 (가격 = 품질 신호)

## 3. 가격 정책 (확정)

브랜드 톤 유지(기존 등급명) + 신규 150,000원 등급 "다이아" 추가. 분양상담사 = 공인중개사 동일 구조.

| 가격(공급가) | 공인중개사 | 분양상담사 | tier id | 기간 구조 |
|---|---|---|---|---|
| 49,000 | BASIC | 프리미엄 | `basic` / `premium` | **7일 + 7일 무료 = 14일 (단일·고정)** |
| 99,000 | 프리미엄 | 슈페리어 | `premium` / `superior` | 10 / 20(+10) / 30일 |
| 150,000 | 다이아 ⭐신규 | 다이아 ⭐신규 | `dia` | 10 / 20(+10) / 30일 |
| 249,000 | VIP | 유니크 | `vip` / `unique` | 10 / 20(+10) / 30일 · **지역 독점·보너스 없음** |
| 0 | 무료 | 무료 | `normal` | 24시간 (기존 유지) |

### 기간별 가격 매트릭스 (공급가, 부가세 10% 별도)

> 보너스 규칙: **"20일 구매 시 +10일 무료"** (입문은 "7일 구매 시 +7일", VIP/유니크는 보너스 없음)
> 노출일 = 구매일 + 보너스일

| 등급 | 10일 | 20일 (+10일 → 30일 노출) | 30일 |
|---|---|---|---|
| 입문(BASIC/프리미엄) | — | — | — *(49,000 / 7+7=14일 단일)* |
| 2단계(프리미엄/슈페리어) | 99,000 (10일) | **198,000 (30일 노출)** | 297,000 (30일) |
| 다이아 | 150,000 (10일) | **300,000 (30일 노출)** | 450,000 (30일) |
| VIP/유니크 | 249,000 (10일) | 498,000 (20일) | 747,000 (30일) |

20일 옵션(+10일)이 30일 옵션보다 같은 30일 노출을 더 싸게 줘서 **주력 SKU**가 되고,
30일 옵션은 "20일이 똑똑한 선택"으로 보이게 하는 **비교 미끼(decoy)** 로 남긴다.

### 특별가 연출 (옵션 B 채택)

- 각 옵션에 **정가(`listPrice`) 취소선 + 할인율(%)** 표시 → "오픈기념 특별가"
- 기본값 규칙: `listPrice = round(price / (1 - 0.33), 1000)` (≈ 33% 할인 연출). **마케팅 조정 가능값.**
  - 입문 예외: 실 49,000 / 정 79,000 (38%↓)
- `listPrice` 미설정(무료 등급 등)이면 취소선 미표시

## 4. 데이터 구조 (`src/lib/toss.ts`) — 단일 출처

`toss.ts`를 가격의 **유일한 출처**로 만든다. `premium/page.tsx`의 `PRICING_DATA`는 가격을 제거하고
표현 정보(features·색상·아이콘·뱃지·stats·FAQ)만 유지한다.

```ts
// 기간 옵션 (한 등급 안의 10/20/30일 각각)
export interface DurationOption {
  days: number;        // 구매 기간 (7, 10, 20, 30)
  bonusDays: number;   // 무료 증정일 (0 | 7 | 10)
  price: number;       // 공급가액 (부가세 별도)
  listPrice?: number;  // 정가 취소선용 (없으면 미표시)
}

// 등급 (입문/2단계/다이아/VIP)
export interface PricingTier {
  id: string;          // 'basic' | 'premium' | 'superior' | 'dia' | 'vip' | 'unique'
  name: string;        // 'BASIC' | '프리미엄' | ...
  category: 'agent' | 'sales';
  exclusive: boolean;  // 지역 독점(VIP/유니크) 여부
  options: DurationOption[];  // 입문은 길이 1, 나머지는 3
}

// 헬퍼
export function getExposureDays(o: DurationOption): number { return o.days + o.bonusDays; }
export function getDiscountRate(o: DurationOption): number | null {
  return o.listPrice && o.listPrice > o.price
    ? Math.round((1 - o.price / o.listPrice) * 100) : null;
}
// 기존 getVat() / getTotalPrice() / generateOrderId() 그대로 재사용
```

데이터는 `Record<string, PricingTier>` 로 유지하되 key = `{category}-{id}` (예: `sales-dia`).
기간옵션 조회 헬퍼: `findOption(category, id, days)`.

## 5. UI / 화면 구조 (`src/app/premium/page.tsx`)

1. **등급 카드 4개**(입문/2단계/다이아/VIP) + 무료 카드 → 그리드 (2×3 또는 5열 반응형)
2. **카드 내부 기간 토글** (2단계·다이아·VIP/유니크만): `[10일] [20일 +10일] [30일]` 세그먼트
   - 변경 시: 가격·정가취소선·할인율·"+10일 무료" 뱃지·"총 노출 N일" 실시간 갱신
   - 상태: `selectedDays[tierId]` (카드별 독립). 기본 선택 = 20일(주력 SKU)
3. **입문 카드**: 토글 없음, "7일+7일 = 14일" 고정 단일
4. **VIP/유니크 카드**: "지역 독점" 뱃지, 보너스 없음
5. CTA → 기존 "공고 선택 모달" 재사용. 모달 푸터에 **선택 등급 + 기간 + 총 노출일 + 결제총액(부가세 포함)** 표시
6. 신규 다이아 노출 혜택 카피: "전용 그리드 상단 고정 + 다이아 배지 + 조회수 강조" (슈페리어/프리미엄 위, 유니크/VIP 아래)

## 6. 결제 플로우

```
premium/page.tsx (등급+기간 선택)
  → handlePayment(tier, days)
  → /checkout?productKey={category}-{id}&days={선택일}&jobId={id}
  → 토스 위젯 (선택 옵션의 price+VAT)
  → /api/payment/confirm (가격 재검증 + expires_at 계산 + 공고 tier 갱신)
  → /payment/success
webhook(/api/payment/webhook)도 동일 로직으로 보정
```

- `productKey = {category}-{id}` 유지(안정적), 기간은 **별도 `days` 파라미터**로 전달
- 서버(confirm/webhook): `findOption(category, id, days)` 로 가격 재검증 (클라 전달 금액 신뢰 금지)
- **노출 만료일** `expires_at = paid_at + getExposureDays(option)일`
  - 입문 14일, 2단계 20일선택 시 30일, 30일선택 시 30일 ...
- 입문은 `days` 생략/7 고정 처리

## 7. TIER_RANK 정비

현재 `premium/page.tsx`의 `TIER_RANK`가 카테고리 혼용이라 신규 등급 추가 시 모호.
**카테고리별 분리**로 변경:

```ts
const TIER_RANK = {
  agent: { normal:0, basic:1, premium:2, dia:3, vip:4 },
  sales: { normal:0, premium:1, superior:2, dia:3, unique:4 },
};
```

업그레이드 가능 판정(`canUpgrade`)은 `TIER_RANK[category]` 기준으로 비교.

## 10. 비범위 (Out of Scope)

- 분양의신식 "보유 머니 충전" 선불 지갑 — 도입 안 함 (건별 결제 유지)

- 기존 결제 데이터 마이그레이션 — 실 결제 없음 → 불필요

## 11. 롤아웃

- 테스트 미끼가 → 실가 승격: 실 결제 고객 없어 호환성 이슈 없음
- "오픈기념 특별가"(listPrice 취소선)로 가격 인상 명분 확보
- 무료(24시간) 등급은 그대로 유지 (진입 유입 채널)
