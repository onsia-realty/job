# 단기임대 공개 응답 및 DB 권한 — 적용 전 점검

## 2026-10-20 공개 범위 갱신

- 공개 목록: 개설등록번호·중개사 전화번호 제외. 공개 상세: 중개사 매물에 한해 등록번호를 제공하고 하단 '담당 중개사' 블록 한 곳에 표시한다.
- 상세 사무소 연락처는 `broker_offices.tel_no`를 등록번호로 조회한다. 기존 스냅샷의 `users.phone` fallback을 공개하지 않으며 미매칭/오류/빈 번호는 연락처 비공개·기존 문의 기능으로 처리한다. 인증된 소유자/관리자 관리 응답과 서버 저장·인증은 유지한다.
- 직접등록 매물에는 오래된 중개사 신원·연락처 스냅샷도 노출하지 않는다. 개인 전화/이름/카카오·상세 호실·사용자ID·내부 리드 필드는 공개 응답에서 계속 제외하며 `private, no-store`·`Vary: Authorization`을 유지한다.
- 전체37파일537테스트 통과. 운영 익명 Supabase 직접 stays/개인정보 컬럼 HEAD401 확인. 실제 사용자별 전체 DB 권한 검증을 대신하지 않으며 DB 쓰기/마이그레이션은 하지 않았다. 아래 적용 전·등록번호 전체 비노출 설명은 이전 이력이다.
- 자유입력 설명·주소·사진 안 개인정보는 자동 탐지/삭제하지 않는다. 광고 승인 시 별도 검토가 필요하다.

갱신: 2026-10-16. API 코드는 `main` / `007e4d4`에 병합돼 있다. 운영039 정책·046 컬럼 존재는 확인했지만 042를 포함한039~046 전량 파일 적용 이력과 STAY 실계정별 전체 검증·앱 배포는 후속이다. 백업 파일 존재만으로 적용을 판단하지 않는다.

후속 사용자 승인으로 운영 결제/집계 047/048을 적용했다. 039 정책·046 컬럼 존재와 구조·권한34·실제 DB ROLLBACK 통합15검사, 기존 데이터 fingerprint 동일을 확인했다. 이는 STAY 042의 전체 실제 계정별 읽기 검증을 대체하지 않는다. 운영 migration 이력 테이블이 없으므로 카탈로그·실행 결과를 근거로 하며 앱 배포·실카드 결제는 하지 않았다.

공개 API는 검토된 광고 필드만 반환한다. 임대인 이름/전화/카카오 링크, 상세 호실 주소, 사용자 ID, 내부 리드·건물 식별자는 제외한다. 현재 로컬 미커밋 변경은 중개사 등록번호도 공개 DTO·화면에서 제외하며 사무소명·소재지·연락처·대표자 4개 필드를 제공한다. 이는 코드의 필드 범위 설명이고 법률 적합성을 판단한 것이 아니다. 자유입력 설명·주소·사진 자체에 기재된 연락처나 상세 호실까지 자동 삭제하는 기능은 없으므로 승인 시 검토한다.

## 동작

- 비로그인 및 타 사용자: 승인·활성 매물 공개 DTO만 조회.
- 소유자/관리자 상세, 본인 목록: 인증 후 비공개 필드를 포함한 관리용 응답. 응답은 private/no-store.
- 신규 등록은 사업자·사무소 인증 여부와 관계없이 승인 대기. 사무소 인증은 개별 광고·사진 사용권의 증명이 아니다. 관리자는 소유/위임과 사진 이용 허락을 별도 확인·기록한 후 공개한다.
- 매물 내용 수정 요청은 다시 승인 대기로 전환한다. 상태/숨김만 수정하는 요청은 기존 승인을 유지한다. 변경값을 비교하지 않으므로 전체 폼 재저장도 재검토 대상이다.
- DB 직접 클라이언트 접근: 익명 조회/쓰기는 차단, 로그인 사용자는 본인 행 조회만 가능. 관리자 API와 작성·수정 API는 기존 service_role 경로를 유지한다.

## 마이그레이션

042_stays_private_reads.sql은 001~038 테이블·함수가 존재하면 039/040/041 없이도 stays 범위를 독립적으로 보호한다. 다른 테이블의 039 보안을 대신하지 않는다. 신규 환경은 순서대로 적용하고, 기존 환경에서는 실제 적용 이력과 정책을 먼저 확인한다. 039를 나중에 실행하면 공개 SELECT 정책을 다시 만들므로 반드시 042를 마지막에 다시 실행한다.

적용 전에 stays 정책·테이블/컬럼 권한·의존 뷰/RPC 정의를 백업하고 확인한다. 042는 stays의 모든 기존 정책과 클라이언트 쓰기 권한을 교체한다. 저장된 데이터는 변경하지 않는다. 기존 dashboard 전용 SECURITY DEFINER 뷰/RPC는 테이블 RLS를 우회할 수 있으므로 종속관계와 공개 EXECUTE/SELECT 권한을 별도 점검해야 한다. 공개용 뷰는 새로 만들지 않는다.

## 운영 전 실제 DB 검증

테스트 프로젝트에서 035~038 상태와 039/040 적용 상태 각각에 042를 적용해 다음을 확인한다.

1. 익명 REST stays 전체/개인정보 컬럼 SELECT와 INSERT/UPDATE/DELETE 실패.
2. 사용자 A는 자기 행만 조회, 사용자 B와 익명은 A의 승인된 행에서도 전화번호 조회 불가.
3. 사용자 A의 직접 승인 필드 변경·새 매물 INSERT 불가, 인증 API 등록/수정·관리자 승인 성공.
4. 공개 목록/상세에서 비공개 필드와 미승인 행 부재. 본인 수정 폼과 관리자 화면은 정상.
5. 숨긴 매물 조회수 RPC는 값을 바꾸지 않으며 익명 RPC 직접 실행은 실패.
6. 소유자 상세를 먼저 읽어도 다음 익명 응답에 개인정보가 캐시되어 나오지 않음.
