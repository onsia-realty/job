오픈 전 점검 작업 중에는 다음 원칙을 따른다:
- 작은 수정(오타, 누락 prop, 단순 스타일, 명백한 버그): 즉시 fix, 사후 보고
- 큰 변경(스키마 변경, RLS 정책 신설, 파일 구조 변경, 의존성 추가, 동작 의미 변경): 사용자에게 먼저 확인
- 매 단계마다 자가 검증(타입체크/실행 흐름 추적) 후 다음으로 넘어간다

**Why:** 사용자가 명시적으로 "크게 변경건이 아니면 진행해, 오픈하기 전 체크하고 문제점을 찾은거니깐"이라고 위임. 점검 페이즈에서 일일이 묻는 건 비효율이고, 문제 찾기 자체가 목표.

**How to apply:** 오픈 전/QA/체크리스트 작업 중에만 적용. 신규 기능 개발이나 v2 작업에는 적용하지 않음(거기는 다시 확인 받기). 변경 후 `npm run build` 또는 타입체크로 회귀 없는지 검증.
